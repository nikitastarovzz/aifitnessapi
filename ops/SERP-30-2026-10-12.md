# 30 changes from a search-results study — 2026-10-12

How aifitnessapi.com comes up for its own name and for 30 queries built on
"fitness api", and what to change. Written 2026-10-12.

## Method, and what could not be done

- **Google's results page could not be read directly.** From this environment
  Google answers an automated browser with its "unusual traffic" CAPTCHA, and
  a plain request gets a JavaScript-only redirect. Getting around that is not
  something we do. Google's own view comes from Search Console instead: the
  live pull for 2026-09-12 to 2026-10-09 (`data/gsc/latest.json`), by query,
  by page and by query × page.
- **Who else ranks** comes from 31 searches in the session's web search tool
  (not Google, and US-only): the brand, "fitness api" and 29 variants. The
  tracked set is listed at the end, so the study can be repeated.
- Search Console's URL Inspection API was not reachable (the read-only
  credential covers the `webmasters/v3` host only).

## Findings

1. **The head term is split across seven of our pages.** Google showed seven
   different pages of ours for "fitness api" (94 impressions, 1 click,
   position 28.3 at query level): the homepage at 18.5 (56 impressions),
   /alternatives at 29.8 (30), /learn 43.0 (19), /blog 54.1 (16), /compare
   58.8, /pricing 94.8, and /fitness-apis at 11.0 for a single impression.
   Six hubs carry near-identical titles ("Fitness & Health API … ·
   AIFitnessAPI"), so Google keeps testing all of them and ranks none.
2. **The pages built for the intent are invisible.** The /fitness-apis
   pillar ("Best Fitness & Workout APIs (2026)") had 4 impressions; the /apis
   directory 1; /fitness-apis/free-fitness-apis none in 28 days.
3. **The head-term results are a list intent.** The search tool returned
   listicles and directories for every generic query: Zyla Labs' blog (ten or
   more posts per query, promoting its own hub), RapidAPI collections,
   publicapis.io, apitracker.io, MirrorFly's "14 Fitness APIs", VideoSDK's
   "ultimate guide", and Google's own Fit and Health API docs. Aggregator
   vendors (Spike, Terra, Vital/Junction, Human API, Sahha) own "wearable data
   api", and Sahha publishes the Google Fit sunset and "alternatives" pages we
   also cover. Registries and GitHub own "python" and "react native".
4. **The brand is not a query.** Search Console shows no impressions for
   "aifitnessapi", "ai fitness api" or "kinestex"; the search tool found nothing
   of ours for "aifitnessapi". "AIFitnessAPI" reads as one token, so the brand
   does not match "ai fitness api", where Zyla ranks.
5. **We are in the third-party index, with stale copies.** Restricted to our
   domain, the tool returned ten of our pages with old titles (" -
   AIFitnessAPI" suffixes) and old statements (Garmin sign-ups "paused", the
   Fitbit date "to be confirmed"), and one `www.` URL. IndexNow runs after
   every deploy and succeeds, so this is the other index's crawl lag.
6. **7% of Google impressions still land on `www.` URLs** (46 pages, 1,073
   impressions, 5 clicks), although `www` 308s to the apex and every canonical
   names the apex. Google is consolidating; nothing to fix, but worth watching.
7. **No search appearance.** Search Console reports no rich-result appearance
   at all. FAQ rich results are limited to authoritative health and government
   sites and HowTo results are gone, so the markup we carry will not earn them;
   titles and descriptions carry the weight.
8. **Small technical gaps.** `/favicon.ico` returns 404 (only an SVG icon is
   served, and Bing and many link-preview clients still ask for the .ico). The
   Organization markup has no logo, and its only `sameAs` is the GitHub repo.
9. Desktop drew 12,708 impressions at 1.0% CTR, mobile 1,622 at 1.9%; the US
   desktop block explains most of the gap (GROWTH-30 #24).

### A. Own "fitness api" with the page Google already prefers

   homepage best for "fitness api" (18.5); its title leads with the brand.
   Lead with "Fitness APIs" and let the WebSite name supply the site name.

   glance" table generated from the cost model: every product, its category,
   how it bills and whether approval gates launch, each linking to its
   directory page. No new claims; the list intent the ranking pages serve.
_Status 2026-10-12: done — the definition capsule from /learn/what-is-a-fitness-api and a 24-row table (category, billing, approval gate, user-side cost) linking each product's entry, with the funding note._
3. **Hub titles stop competing for the head term [P].** /alternatives,
   /compare, /learn, /blog, /pricing and /apis get titles that lead with what
   each hub is for, instead of six variations of "Fitness & Health API".
_Status 2026-10-12: done for eight hubs (/fix already had its own): /alternatives, /compare, /pricing, /learn, /blog, /migrate, /glossary and /apis. H1s unchanged._

## Found in passing

- **Words glued together across the site.** The compiler Next ships drops
  the leading space of a JSX text run that contains an HTML entity and spans
  lines, so pages read "5carry", "22unit families", "Disclosure:KinesteX".
  69 runs in 41 files were affected. Each now carries an explicit `{" "}`,
  and a qa gate (JSX-ENTITY-SPACE, listed on /gates) fails the build if one
  comes back.
